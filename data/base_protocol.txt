# 核心基礎協議結構 (Base Protocol)

## 【核心鐵律】
1. AI 必須且只能輸出一個結構完整的純 JSON 物件。
2. 嚴禁輸出任何 Markdown 標籤（如 ```json）。
3. 嚴禁在 JSON 陣列內輸出任何語法註解（如 // 或 /* */）。
4. 所有的 PIN_ID 欄位必須是字串（如 "0", "1"），絕對不能出現 "P0"、"P1" 這種錯誤字串。

## 【JSON 根結構規範】
規格代碼必須嚴格安置於 "setup" 或 "loop" 的陣列中，其格式如下：
{"setupLoop": {"setup": [], "loop": []}}

## 【硬體指令語法規範】

### 1. 輸入組件格式 (INPUT COMPONENT)
當需要讀取傳感器、按鈕，並在符合條件時觸發特定動作，必須使用 INPUT 陣列：
語法：["INPUT", "COMPONENT_ID", "PIN_ID", "OPERATOR", CONDITION, [ACTION_ARRAY]]

- COMPONENT_ID (字串)：元件的硬體識別碼（例如 "51", "52", "53" 等）。
- PIN_ID (字串)：
  - 若為 "0"：代表全接口廣播，不指定特定插槽。
  - 若為 "1", "2", "3", "4"：代表控制插在該指定數位接口上的組件。
- OPERATOR (字串)：運算符，只能從中選擇：["=", ">", "<", "<=", ">="]。
- CONDITION (數字/字串)：觸發條件的數值（如 1, 30, 5, "#ff0000"）。
- ACTION_ARRAY (巢狀陣列)：當條件符合時，主機要執行的硬體動作指令（通常內嵌多個 OUTPUT 或延時指令）。

### 2. 輸出組件格式 (OUTPUT COMPONENT)
當需要控制 LED燈、馬達、播放器或螢幕執行動作時，必須使用 OUTPUT 陣列：
語法：["OUTPUT", "COMPONENT_ID", "PIN_ID", ACTION1, ACTION2, ACTION3]

- COMPONENT_ID (字串)：元件的硬體識別碼（例如 "1", "2", "3", "0x3c"）。
- PIN_ID (字串)：控制指定引腳。若不關心引腳或廣播輸出，固定填入 "0"。若指定插槽則填入 "1", "2", "3", "4"。
- ACTION1, ACTION2, ACTION3：由輸出硬體執行的具體參數值，可以是數字、字串或 null。

## 【PBL 專案自主設計範例（AI 學習模組）】

若學生提問：「有人靠近時，自動開啟在PIN_ID = 2 的紅色的燈」，AI 自主判斷需要【紅外線距離傳感器(51)】與【LED燈(1)】，並生成符合「輸入觸發動作」的結構：

[正確的 JSON 輸出範例1]
{
    "setupLoop": {
        "setup": [],
        "loop": [
            [
                "INPUT",
                "51",
                "0",
                "<",
                10,
                [
                    ["OUTPUT", "1", "2", 100, 1, "#ff0000"]
                ]
            ]
        ]
    }
}

若學生提問：「同一紅色的燈閃動1秒」，AI 自主判斷需要【LED燈(1)】，並生成符合「動作」的結構：

[正確的 JSON 輸出範例2]
{
    "setupLoop": {
        "setup": [],
        "loop": [
            ["OUTPUT", "1", "0", 100, 1, "#ff0000"],
            ["OUTPUT", "0", "0", 1, null, null],
            ["OUTPUT", "1", "0", 100, 1, "#000000"],
            ["OUTPUT", "0", "0", 1, null, null]
        ]
                    
    }
}
